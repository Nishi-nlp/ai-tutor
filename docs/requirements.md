## AIチューター学習システム　要件定義書

## 1. プロジェクト概要

### 1.1 システム名

Adaptive AI Tutor for Mathematics and Machine Learning

### 1.2 目的

ユーザーが学習したい内容（この場合、線形代数・Deeplearning、PRML）のPDF教科書とAIチューターを用いて学習できるWebアプリケーションを開発する。

本システムは、単にPDFへ質問できるRAGチャットではなく、以下の学習理論・技術を組み合わせる。

- RAG
  - 教科書を根拠に説明・ヒント・問題を生成する
- Knowledge Component
  - 学習内容を理解可能な小さな知識単位に分解する
- Knowledge Tracing
  - 学習者が各知識を習得している確率を推定する
- Mastery Learning
  - 十分に理解するまで補習と再評価を繰り返す
- ACT-R
  - 記憶の減衰や検索のしやすさを考慮して復習時期を決める
- ICAP
  - 受動的な閲覧だけでなく、回答・説明・比較・対話を促す

最終的には、学習者ごとに

- 次に何を学ぶか
- 何を復習するか
- どの説明を出すか
- どの問題を出すか

を自動的に調整する**AI家庭教師**を目指す。

## 2. 背景と課題

現在、線形代数やDeep Learningを学ぶための優れた教科書は存在するが、独学では次の問題が起きやすい。

- どこから読めばよいか分からない
- 前提知識が不足していて理解できない
- 読んだだけで理解したつもりになる
- 問題を解かずに進んでしまう
- 分からない箇所を質問できない
- 忘れた内容を適切な時期に復習できない
- 数学と実際の機械学習・コードの関係が分かりにくい
- 教科書ごとの説明や難易度の違いを統合しにくい

本システムでは、教科書を知識源として利用しつつ、学習者の理解状態に合わせて説明・問題・復習を調整する。

## 5. 学習対象と学習順序

### 5.1 基本方針

教科書の章をそのまま一つのレッスンにはしない。

学習内容を、評価可能な最小単位である**Knowledge Component（KC）**に分割する。

```
線形代数
├── ベクトル
│   ├── ベクトルの表記
│   ├── ベクトル加算
│   ├── スカラー倍
│   └── 線形結合
├── 行列
│   ├── 行列の表記
│   ├── 行列ベクトル積
│   ├── 行列積
│   └── 逆行列
├── ベクトル空間
│   ├── Span
│   ├── 線形独立
│   ├── 基底
│   └── 次元
└── 固有値・SVD
    ├── 固有値
    ├── 固有ベクトル
    ├── 対角化
    ├── SVD
    └── PCA
```

### 5.2 教材間の接続

同一のKCに複数教材の参照を紐づける。
PDFごとに独立したコースを作るのではなく、KCを中心に教材を統合する。

## 6. 学習理論の適用方針

### 6.1 Knowledge Component

#### 目的

何を理解できていて、何が理解できていないかを追跡できる粒度に学習内容を分解する。

#### KCが持つ情報

```
ID
名称
説明
学習目標
前提KC
後続KC
関連教材
関連ページ
重要度
難易度
問題タイプ
習得基準
```

#### 例

```json
{
  "id": "la.matrix_vector_product",
  "name": "行列ベクトル積",
  "learning_objectives": [
    "行列ベクトル積を計算できる",
    "列ベクトルの線形結合として説明できる",
    "線形変換として解釈できる"
  ],
  "prerequisites": [
    "la.vector",
    "la.linear_combination"
  ],
  "applications": [
    "dl.dense_layer"
  ]
}
```

### 6.2 Knowledge Tracing

#### 目的

各KCについて、学習者が習得している可能性を推定する。

#### MVP

最初は高度なDeep Knowledge Tracingを使わず、回答評価の点数と
ヒント使用レベルから簡易Mastery Scoreを計算する。

- 固定回答、数値・数式、Pythonコード、説明問題などの評価結果は、
  共通の4段階評価へ変換する
- 4段階評価の点数にヒント係数を掛けて、回答ごとの学習証拠を計算する
- 問題難易度による重み付けはMVPでは行わない
- 回答時間は記録してもよいが、MVPのMastery計算には使用しない
- 具体的な点数、係数、更新式は`docs/mastery-policy.md`で定義する

#### 初期ステータス

```
未学習
学習中
要復習
習得
```

#### 将来実装

MVP後にBayesian Knowledge Tracingへ置き換える。

BKTで管理する値：

```
P(L0): 初期習得確率
P(T): 学習遷移確率
P(G): 推測による正解確率
P(S): 理解している場合の失敗確率
P(Ln): 現時点での習得確率
```

KCごとに習得確率を保持し、回答のたびに更新する。

### 6.3 Mastery Learning

#### 目的

未理解のまま後続内容へ進むことを防ぐ。

#### 基本フロー

```
事前確認
↓
説明
↓
例題
↓
練習
↓
評価
↓
習得基準を満たしたか
├── はい → 次のKC
└── いいえ → 別の説明・補習・追加問題
```

#### MVPの習得基準

KCの習得判定は、単純な正答率だけで決めない。

- Mastery Scoreが0.85以上
- ヒントなしの完全正解が1回以上
- 異なる2種類以上の問題形式で成功

具体的な判定方法は`docs/mastery-policy.md`で定義する。数値を変更する場合は、
計算方式のバージョンを更新し、変更理由と結果を記録する。

#### 再学習方法

理解不足の場合、同じ説明を繰り返すのではなく、以下から選択する。

- より簡単な説明
- 図による説明
- 具体例
- 前提KCの復習
- 類題
- 穴埋め問題
- ステップ分解
- NumPyでの実験
- Deep Learningでの利用例

### 6.4 ACT-R

#### 目的

学習直後の正答だけでなく、時間経過による忘却を考慮する。

#### 利用範囲

ACT-R全体を忠実に実装するのではなく、MVPでは固定された復習間隔と
回答履歴に基づく簡易方式を使用する。

主に次を扱う。

- 何回学習したか
- いつ学習したか
- 学習間隔
- 最近の正誤
- 想起に必要だったヒント

回答時間は記録してもよいが、MVPの復習対象選定と優先度計算には使用しない。
回答時間や回答速度を記憶の強さへ反映することは、MVP後の検討対象とする。

#### 復習優先度

以下のような値から復習優先度を計算する。

```
復習優先度 =
忘却リスク
× KCの重要度
× 後続KCへの影響
× 最近の誤答度
```

#### ACT-R由来の設計方針

- 一度に大量反復するより、時間を空けた反復を重視する
- 見直すだけでなく、答えを思い出させる
- MVP後は、回答速度を記憶の強さの指標として利用することを検討する
- 繰り返し成功しているKCは復習間隔を延ばす
- 長期間使っていないKCはMasteryを再評価する

### 6.5 ICAP

#### 目的

PDFを読んで終わる受動的学習を避ける。

ICAPの4段階に応じた学習活動を用意する。

#### Passive

情報を受け取るだけ。

- 教科書を読む
- 解説を見る
- 動画を見る
- AIの回答を読む

Passiveだけでレッスンを完了させない。

#### Active

学習内容を操作する。

- 重要部分を選ぶ
- 式の一部を埋める
- ベクトルや行列を計算する
- コードを実行する
- 図のパラメータを変更する

#### Constructive

学習者が新しい表現を生成する。

- 自分の言葉で説明する
- 例を作る
- 導出の続きを書く
- Pythonで再現する
- 複数概念の違いを説明する
- 誤答の理由を説明する

#### Interactive

AIと相互に説明を構築する。

- AIの質問に答える
- AIへ質問する
- AIの誤った説明を訂正する
- 解法を比較する
- Socratic Dialogueを行う
- 学習者とAIが交互に証明や導出を進める

#### レッスン要件

各KCのレッスンには、原則として以下を含める。

```
Passive: 短い説明
Active: 計算または操作
Constructive: 自分の言葉で説明
Interactive: AIとの対話
```

## 7. RAG要件

### 7.1 目的

AIの回答を一般知識だけに依存させず、利用者が登録した教科書の記述を根拠にする。

### 7.2 基本処理

```
PDF登録
↓
ページ解析
↓
章・節・段落・図・数式を抽出
↓
チャンク作成
↓
Embedding生成
↓
Vector Storeへ保存
↓
KC・教材ページと関連付け
↓
検索
↓
LLMが回答生成
↓
出典ページを表示
```

### 7.3 チャンク単位

固定文字数だけで切らない。

優先順位：

1. 章
2. 節
3. 小見出し
4. 段落
5. 定義
6. 例題
7. 図とキャプション
8. 数式と周辺説明
9. 演習問題

各チャンクには次のメタデータを付ける。

```json
{
  "document_id": "strang",
  "page_start": 31,
  "page_end": 32,
  "chapter": "1",
  "section": "1.2",
  "content_type": "definition",
  "knowledge_components": [
    "la.linear_combination"
  ]
}
```

### 7.4 検索方法

ハイブリッド検索を採用する。

- ベクトル検索
- キーワード検索
- KCによる絞り込み
- 教材による絞り込み
- ページ・章による絞り込み

検索結果は可能なら再ランキングする。

### 7.5 回答要件

AIは以下を明確に区別する。

- 教科書に明示されている内容
- 教科書から妥当に導ける説明
- AIによる補足
- 他教材からの補足

教科書にない内容を、教科書に書かれているように提示してはならない。

#### 回答表示例

```
回答

教科書での根拠
・Strang p.XX
・Goodfellow p.XX

補足
・AIによる具体例
```

### 7.6 図・数式への対応

StrangのPDFは画像中心なので、テキストだけのRAGでは不十分である。

将来的には以下を扱う。

- PDFページ画像
- 数式認識
- 図と本文の対応関係
- グラフや幾何図形の説明
- マルチモーダルモデルによるページ理解

MVPではまず、対象ページを限定して手動確認したテキストまたはMarkdownを登録してもよい。

#### 将来

- 複数版の対応
- 図・式の個別管理

### 8.2 スキルツリー

- KC一覧を表示する
- 前提関係を表示する
- 学習順序を表示する
- 各KCの習得状態を表示する
- KCから関連教材へ移動できる
- 後続するDeep Learning概念を表示する

例：

```
行列ベクトル積
↓
線形変換
↓
全結合層
↓
ニューラルネットワーク
```

### 8.3 レッスン

各レッスンに以下を表示する。

- タイトル
- 学習目標
- 前提知識
- 教科書の該当箇所
- 短い説明
- 定義
- 具体例
- 図または数式
- 機械学習との関係
- 確認問題
- 説明問題
- Python演習
- AI質問欄
- 現在のMastery
- 次に行う学習活動

### 8.4 AIチューター

#### 質問応答

- 現在のKCと該当教材を優先して検索する
- 回答に参照教材とページを表示する
- 学習者の理解度に合わせて説明の難易度を変える
- 必要に応じて前提KCへ戻る
- 数式を段階的に説明する
- MVPではNumPyでの実装例を提示する

#### Socratic Mode

すぐに答えを出さず、質問によって理解を促す。

例：

```
AI:
この行列の各列をベクトルとして見ると、
Axはどのような線形結合になるでしょうか？
```

#### Explain-back Mode

AIが学習者へ説明を求める。

```
「固有ベクトル」を、数式を使わずに説明してください。
```

AIは以下を評価する。

- 必須概念が含まれているか
- 誤解がないか
- 具体例があるか
- 関連概念との区別ができているか

### 8.5 問題機能

#### 問題タイプ

- ○×
- 選択式
- 数値入力
- 数式入力
- 穴埋め
- 記述
- 証明・導出
- 誤り訂正
- 概念比較
- Python実装
- コード読解
- Deep Learningへの応用

#### 問題の生成方式

#### 事前生成

正答の安定性が重要な問題。

- 基本計算
- 定義問題
- 代表的な例題
- 習得判定問題

#### オンデマンド生成

個別適応が必要な問題。

- 類題
- 苦手箇所の追加問題
- 異なる文脈での問題
- 説明問題
- 応用問題

#### 問題検証

AIが生成した問題をそのまま習得判定には使わない。

- 数値問題：Python、NumPy、SymPyで検証
- 選択問題：正答と根拠を保存
- コード問題：テストコードで検証
- 記述問題：評価基準と必須概念で採点

### 8.6 ヒント機能

ヒントは段階的に出す。

```
レベル1：着目点
レベル2：使用する概念
レベル3：途中式
レベル4：ほぼ解答
レベル5：完全解説
```

ヒント使用量はMasteryの更新に反映する。

正解しても、強いヒントを使った場合は習得済みと即断しない。

### 8.7 Python演習

#### 対象

- NumPy
- Matplotlib
- SymPy

PyTorchを使用する演習はMVP対象外とし、将来のサーバー側コード実行環境で
対応を検討する。

#### 例

- ベクトル加算を実装する
- 行列積を計算する
- 行列を線形変換として可視化する
- 固有値・固有ベクトルを求める
- PCAを実装する
- 全結合層をNumPyで実装する
- Backpropagationの一部を実装する

#### 実行方式

MVPではブラウザ内のPyodideをWeb Worker上で実行する。
バックエンドの隔離されたコード実行環境は、MVP後の検討対象とする。

外部ユーザーへ公開する場合は、任意コードを通常のAPIサーバー上で直接実行しない。

### 8.8 進捗管理

KCごとに以下を保存する。

```
現在のMastery
学習回数
問題回答数
正答率
ヒント使用数
平均回答時間
最終学習日時
次回復習日時
習得状態
過去のMastery推移
```

### 8.9 復習機能

ホーム画面に「今日の復習」を表示する。

復習対象は以下から選ぶ。

- 忘却リスクが高い
- 最近間違えた
- ヒント依存が強い
- 後続KCに必要
- 一度習得したが長期間利用していない
- 説明問題で理解不足が見つかった

回答時間は記録してもよいが、MVPの復習対象選定には使用しない。

復習では、前回とまったく同じ問題だけを出さない。

## 9. 非機能要件

### 9.1 正確性

- 教科書の参照ページを表示する
- RAGの根拠が不足している場合は、その旨を表示する
- 数値問題は可能な限りプログラムで検証する
- AI生成コンテンツと人間が確認したコンテンツを区別する
- 学習目標に使う主要問題は事前確認する

### 9.2 応答速度

目標値：

- レッスン表示：2秒以内
- RAG検索：2秒以内
- AI回答開始：5秒以内
- 通常問題の採点：2秒以内
- コード実行：10秒以内

### 9.3 セキュリティ

- APIキーをフロントエンドへ公開しない
- PDFアクセス権限を制御する
- アップロードファイルを検証する
- コード実行環境を隔離する
- 実行時間、メモリ、ネットワークを制限する
- プロンプトインジェクションを考慮する

### 9.4 著作権

- 教材本文を無断で公開・再配布しない
- PDFはユーザー本人が利用権を持つものに限定する
- 回答には必要以上の長文引用を含めない
- 教材のライセンス情報を保存する
- 公開版ではページ参照と自作教材を中心とする

### 9.5 拡張性

将来的に以下を追加できる構造とする。

- 他の数学教材
- 統計学
- NLP
- Transformer
- 複数ユーザー
- 教師用画面
- DKT・SAKT・AKT
- 学習ログ分析
- A/Bテスト
