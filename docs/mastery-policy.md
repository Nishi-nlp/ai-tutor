# Mastery Policy

## 1. 文書の目的

本書は、回答結果からKnowledge Component（KC）ごとのMasteryを更新し、
復習対象と次回復習日を決定するためのMVP向けルールを定義する。

本ポリシーの数値は仮の初期値であり、実際の利用結果を確認しながら調整する。

## 2. 基本原則

- MasteryはKC単位で管理する。
- Masteryは理解度そのものではなく、回答履歴から推定した値として扱う。
- 正答状況とヒント使用量を分けて記録する。
- Masteryの更新はプログラムで行い、LLMには直接決定させない。
- LLMは記述問題の評価を補助できる。
- 一問の結果だけでMasteryを大きく変化させない。
- 回答時間はMVPのMastery計算に使用しない。
- 問題難易度による重み付けはMVPでは行わない。
- 元の回答履歴を保存し、計算方式の変更後に再計算できるようにする。

## 3. 回答評価

回答結果は、評価方法にかかわらず次の4段階へ変換する。

| 評価 | 点数 |
|---|---:|
| 完全正解 | 1.00 |
| 軽微なミス | 0.75 |
| 部分的に正しい | 0.40 |
| 不正解 | 0.00 |

### 3.1 完全正解

対象KCの学習目標を満たし、重要な誤りがない回答。

### 3.2 軽微なミス

対象KCの考え方や手法は理解しているが、符号、転記、単純計算などに
小さな誤りがある回答。

誤りが対象KCの学習目標そのものである場合は、軽微なミスとはしない。

### 3.3 部分的に正しい

必要な考え方の一部は含まれているが、回答を完成できていない、
または重要な概念が不足している回答。

### 3.4 不正解

対象KCの理解を示す十分な証拠がない、または重大な誤解が含まれる回答。

## 4. 問題形式ごとの評価方法

| 問題形式 | 評価方法 |
|---|---|
| 選択式・固定回答 | 保存された正答と比較する |
| 数値・数式 | NumPyまたはSymPyで検証する |
| Pythonコード | Pyodideでテストを実行する |
| 記述・Explain-back | 評価基準を与えてLLMで評価する |

LLMによる評価結果も、最終的には「完全正解・軽微なミス・部分的に正しい・
不正解」のいずれかへ変換する。

回答履歴には、評価方法、評価結果、評価理由を保存する。

## 5. ヒント評価

ヒントは次の5段階とする。

| ヒント | 内容 | 係数 |
|---|---|---:|
| なし | ヒントを使用していない | 1.00 |
| レベル1 | 着目点 | 0.90 |
| レベル2 | 使用する概念 | 0.75 |
| レベル3 | 途中式 | 0.55 |
| レベル4 | ほぼ解答 | 0.30 |
| レベル5 | 完全解説 | 0.10 |

複数のヒントを使用した場合は、最終回答を提出する前に表示した最も高い
ヒントレベルを使用する。

## 6. 学習証拠の計算

回答ごとの学習証拠を`evidence`として、0から1の範囲で計算する。

```text
evidence
=
回答評価の点数
×
ヒント係数
```

例：

```text
完全正解・ヒントなし
1.00 × 1.00 = 1.00

完全正解・レベル2ヒント
1.00 × 0.75 = 0.75

軽微なミス・ヒントなし
0.75 × 1.00 = 0.75

部分的正解・レベル3ヒント
0.40 × 0.55 = 0.22
```

## 7. Mastery Scoreの更新

各KCのMastery Scoreは0から1の範囲で保持する。

初期値は次のとおりとする。

```text
initial_mastery = 0.20
```

今回の`evidence`が現在のMastery以上の場合は、次の式で更新する。

```text
new_mastery
=
current_mastery
+
0.35 × (evidence - current_mastery)
```

今回の`evidence`が現在のMastery未満の場合は、次の式で更新する。

```text
new_mastery
=
current_mastery
+
0.15 × (evidence - current_mastery)
```

最後に0から1の範囲へ収める。

```text
new_mastery = clamp(new_mastery, 0, 1)
```

データベースには丸める前の値を保存し、画面表示時に小数点以下を丸める。

### 7.1 更新例

初期状態から、ヒントなしで3回完全正解した場合：

```text
初期値：0.200

1回目：0.480
2回目：0.662
3回目：0.780
```

その後、一度不正解だった場合：

```text
0.780 + 0.15 × (0.000 - 0.780)
= 0.663
```

一度の不正解でMasteryをゼロに戻さず、再確認が必要な状態として扱う。

## 8. 習得状態

KCは次の状態を持つ。

```text
未学習
学習中
習得
要復習
```

### 8.1 未学習

対象KCの回答履歴が存在しない状態。

### 8.2 学習中

回答履歴は存在するが、習得条件を満たしていない状態。

### 8.3 習得

次の条件をすべて満たした状態。

```text
Mastery Scoreが0.85以上
かつ
ヒントなしの完全正解が1回以上
かつ
異なる2種類以上の問題形式で成功
```

問題形式の組み合わせ例：

```text
計算問題とExplain-back問題
数値問題とPython演習
記述問題と応用問題
```

### 8.4 要復習

以前に習得状態になったKCが、次のいずれかを満たした状態。

- 次回復習日を過ぎている
- 最新のevidenceが0.50未満
- Explain-back問題で重大な理解不足が見つかった

## 9. 回答履歴として保存する情報

回答ごとに、少なくとも次の情報を保存する。

```text
対象KC
問題
問題形式
学習者の回答
回答評価
使用したヒントレベル
evidence
評価方法
評価理由
回答日時
Mastery計算方式のバージョン
```

Python演習では、追加で次の情報を保存する。

```text
入力したPythonコード
標準出力
実行結果
エラー内容
テスト結果
Pyodideのバージョン
主要パッケージのバージョン
```

## 10. 復習間隔

MVPでは次の固定された復習段階を使用する。

| 復習段階 | 次回までの間隔 |
|---:|---:|
| 0 | 1日 |
| 1 | 3日 |
| 2 | 7日 |
| 3 | 14日 |
| 4 | 30日 |
| 5 | 60日 |

初めて習得状態になったときは、次のように設定する。

```text
review_stage = 0
next_review_at = 習得日時の1日後
```

## 11. 復習結果による間隔更新

### 11.1 復習成功

```text
条件：
evidence >= 0.80
```

処理：

```text
review_stageを1つ進める
最大値は5とする
次の段階で定義された日数後をnext_review_atにする
状態を習得へ戻す
```

### 11.2 一部理解

```text
条件：
0.50 <= evidence < 0.80
```

処理：

```text
review_stageは変更しない
現在の復習間隔と3日のうち、短い方を次回間隔とする
状態は要復習のままとする
```

計算：

```text
next_interval = min(current_interval, 3日)
```

### 11.3 復習失敗

```text
条件：
evidence < 0.50
```

処理：

```text
review_stageを0へ戻す
next_review_atを翌日に設定する
状態を要復習とする
補習または前提KCの確認を追加する
```

## 12. 復習候補

次のいずれかに該当するKCを復習候補とする。

- 次回復習日を過ぎている
- 最近不正解だった
- ヒントへの依存が見つかった
- 一度習得したが一定期間利用していない
- 次に学ぶKCの前提になっている
- Explain-back問題で理解不足が見つかった

未学習のKCは復習候補ではなく、新規学習対象として扱う。

## 13. 復習優先度

復習候補が複数ある場合は、次の値を0から1の範囲で計算する。

```text
O：期限超過度
W：習得の弱さ
E：最近の誤答度
H：ヒント依存度
P：次のKCの前提か
I：KCの重要度
```

### 13.1 各値の計算

```text
O = min(max(期限超過日数, 0) ÷ 7, 1)

W = 1 - Mastery Score

E = 1 - 直近3回の平均evidence

H = 直近3回の平均ヒントレベル ÷ 5

P = 次に学ぶKCの前提なら1、それ以外は0

I = KCの重要度を0から1へ変換した値
```

回答履歴が3回未満の場合は、存在する回答だけで平均を計算する。

### 13.2 優先度の計算

```text
priority
=
0.30 × O
+ 0.25 × W
+ 0.20 × E
+ 0.10 × H
+ 0.10 × P
+ 0.05 × I
```

画面上で100点満点として扱う場合は、最後に100を掛ける。

```text
priority_score = priority × 100
```

優先度が高いKCから「今日の復習」へ追加する。

回答時間と問題難易度は、MVPの復習優先度には使用しない。

## 14. 復習問題の選択

復習では、前回とまったく同じ問題だけを繰り返さない。

可能な場合は次の順序で問題を選ぶ。

1. 前回と異なる問題
2. 前回と異なる問題形式
3. ヒントなしで回答できる問題
4. Explain-backまたは応用問題
5. 後続KCと関連する問題

復習に失敗した場合は、次の補習から選択する。

- 別の説明
- 具体例
- 前提KCの復習
- 段階的ヒント
- より簡単な類題
- NumPyまたはPyodideによる確認

## 15. バージョン管理

Masteryと復習方針にはバージョンを付ける。

```text
mastery_method = simple_asymmetric_ewma
mastery_version = 1

review_method = fixed_interval_priority
review_version = 1
```

計算式や係数を変更した場合は、既存バージョンを上書きせず、
新しいバージョンを追加する。

元の回答履歴を利用し、新旧方式によるMasteryを比較できるようにする。

## 16. テストケース

### ケース1：連続成功

```text
条件：
異なる2種類以上の問題形式で4回、ヒントなし完全正解

期待：
Masteryが約0.857になる
習得条件を満たす
```

### ケース2：強いヒントへの依存

```text
条件：
レベル4または5のヒントを使って完全正解を繰り返す

期待：
Masteryは少し上がる
ヒントなし正解の条件を満たさないため、習得にはならない
```

### ケース3：習得後の軽微なミス

```text
条件：
習得後に一度だけ軽微なミスをする

期待：
Masteryはわずかに下がる
未学習には戻らない
```

### ケース4：習得後の不正解

```text
条件：
習得後にevidenceが0.50未満になる

期待：
状態が要復習になる
Masteryは下がるがゼロにはならない
```

### ケース5：回答時間

```text
条件：
問題を開いたまま離席する

期待：
回答時間によってMasteryと復習優先度は変化しない
```

### ケース6：復習への連続成功

```text
条件：
各復習でevidenceが0.80以上

期待：
復習間隔が1日、3日、7日、14日、30日、60日と延びる
```

### ケース7：復習失敗

```text
条件：
復習時のevidenceが0.50未満

期待：
復習段階が0へ戻る
翌日に復習が設定される
補習対象になる
```

## 17. 利用後の評価

MVPを実際に使用し、次の点を確認する。

- 習得判定後の復習失敗が多すぎないか
- 理解しているKCが学習中のままになっていないか
- 一度の不正解でMasteryが下がりすぎないか
- ヒントあり正解を過大評価していないか
- 毎日の復習件数が多すぎないか
- Explain-back評価と実際の理解にずれがないか
- 復習間隔が長すぎる、または短すぎないか

パラメータを変更するときは、一度に複数の値を変更せず、変更理由と
結果を記録する。

## 18. 将来拡張

回答履歴が十分に蓄積し、簡易方式では次の問題を解決できない場合に、
BKTなどへの変更を検討する。

- 推測による正解を考慮したい
- 理解していても間違える可能性を考慮したい
- KCごとの学習速度を推定したい
- 簡易Masteryと実際の復習結果に大きなずれがある

BKTへ変更する場合も、既存の回答履歴を入力として再利用する。
